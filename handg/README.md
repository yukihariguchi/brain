# H&G brain

H&G（HGJP / HGSG）とその出資先についての前提集。播口と CFO が読み書きし、Claude などの AI に読ませる前提にもなる。

事実と骨格だけを置く。残す/消すの判定基準は「3ヶ月後に読んで役立つか」。

- 置く: 事実（法人の立て付け・体制・保有・決定事項）、骨格（方針・判断基準・会計ルール・用語）
- 置かない: 議論のログ、検討中のドラフト、月次で変わる数字（数字は会計ソフトを正とする）

## ファイル

| ファイル | 内容 |
|---|---|
| base.md | H&G 本体。資本構成・保有・HGJP と HGSG の役割分担・資金の流れ・用語 |
| haku/base.md | 株式会社白（Haku、飲食。HGJP が 25% 出資） |
| h2t2/base.md | 株式会社H2T2（レストラン YAWYE を運営。H&G が 50% 出資） |
| h2t2/finance.md | H2T2 の会計・経理。マネーフォワードの立て付け・売上と原価の計上・部門・科目ルール |
| sanctuary/base.md | 株式会社サンクチュアリ（バー secret を運営。H&G の出資先） |
| sanctuary/finance.md | サンクチュアリの会計・経理。部門・科目ルール・未解決事項 |

新しい会社が増えたら `<会社名>/base.md` を作る。会計の話が出てきたら `<会社名>/finance.md` に分ける。ファイル名は小文字のケバブケース（例: `hello-dining.md`）。空のファイルは作らない。

## 書き方のルール

- 追記には日付を入れる。形式は `YYYY-MM-DD`（例: 「2026-10-17 追記」「（2026-10-17 決定）」）
- 推測を事実として書かない。未確認のものは「要確認」と明記する
- 決めたことは「決めたこと / 却下した案 / 理由」が分かるように書く。却下した案を残すのは、同じ議論を繰り返さないため
- 古くなった記述は消すか書き換える。履歴は git に残るので、ファイルの中に「旧」を残さない
- 文章は短く。一文一義。略語は初出で展開する
- 変更したら commit して push する。コミットメッセージは「ファイル名: 何を変えたか（日付）」（例: `h2t2/finance.md: 原価の計上ルールを追記（2026-10-17）`）

## 用語

- HGSG: H&G MANAGEMENT PTE. LTD.（シンガポールの資産管理会社）
- HGJP: 株式会社Harry&Gucci（日本の資産管理会社）
- 文中では HGSG / HGJP で書く。正式名称は契約書・登記など正式名称が要るときだけ

## この repo の位置づけ

この repo は、播口が持つ全社横断の brain repo の `handg/` フォルダを `git subtree` で切り出したもの。

- 播口側の変更はこの repo に反映される。この repo での編集も播口側に取り込まれる。どちらで編集してもよい
- 本文中の「播口の brain の me/…」「播口の brain の hello/…」は、この repo に含まれない播口側のファイルを指す。必要なら播口に聞く
