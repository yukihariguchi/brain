# 連絡先とチャットをパーソナルアシスタント基盤の新しい体験に置き換え、ローンチ後にバイラルで広がる前提で、Hello は LINE を disrupt できるか

## 背景（事実）

2026-09-24 時点で播口と Claude が事実として共有しているもの。brain（hello/hello.md・hello/hello-dining.md・decisions.md）に無いものを含む。

### Hello 側

- HelloX は音声 AI の電話サービス（AI エージェント＋クラウド PBX）。0→1 フェーズで PdM・事業開発責任者を募集中
- AutoReserve / HelloX の電話オペレーションを担う 200 人規模の運用部隊がある。AI が完遂できない電話は人が引き取れる。対応言語は日英仏伊西独（中韓台は無い）
- entry（Respo 台帳の無料プラン）の新規契約は AI 電話営業で取っている。播口の評価は「数も原価も人より圧倒的に良い」。人の電話営業は月 約 1,000 件だった
- entry はユーザーが AR に予約手数料を払うモデル。店側の承認で確定し、非同期
- 2026 上期の AR の分析: 行き先と店は Instagram・TikTok・Google で決まり、ユーザーは店名検索で AR に来て予約だけする。AR は「他で決めた店を予約する場所」
- 播口の見立て: 日本語の音声対音声（audio-to-audio、AtoA）モデルの精度はまだ低く、エージェントが日本語の電話を完遂できるまで 1 年ほどかかる。テキストのチャットは日本語でも問題ない

### 汎用エージェントの現況（2026-09、Web で確認）

- Meta の Muse は 2026-09-08 に米国で公開。2 週間で 250 万ダウンロード、米国のチャート 1 位（Sensor Tower）。自社アプリと WhatsApp の中で動く
- Muse の電話機能は 2026-09-16 に米国内の店向けベータで開始。米国限定・英語のみ。Reuters（09-23）と 404 Media は、電話の一部を人間のコールセンター契約者が代行し、かけた側も受けた側も事後まで知らされない例があったと報道。店に切られた失敗例も報告あり。成功率は非公表。Meta は「内部テスト中、開示を整えてから公開」と回答
- 競合の Instinct も同週に電話機能を早期アクセスで開始。米国限定
- Bloomberg（09-22）: Muse の登場で「消費者の慣性に依存する銘柄」（銀行・保険・旅行）が売られた
- Muse の発見（ディスカバリー）は Instagram・Facebook のグラフとリール（インフルエンサーの言及・エンゲージメント）を使う。他の LLM はこのデータを持たない

### LINE ヤフー（Web で確認）

- Agent i を 2026-04-20 に発表。2026 上期に 20 領域以上のエージェント。「別アプリに遷移せず、対話の中で予約・購入まで完了」を掲げる。航空券手配は 2026 夏まで
- Agent i in chat（トークルーム内でエージェントを呼ぶ）: 2026 年内提供予定
- LINE OA AI モード（店の公式アカウントを AI 接客に）: 2026 夏頃から。Agent i Biz: 2026-08 から
- 収益モデルは広告・課金・手数料（Ledge.ai 2026-05-13 の見出し。詳細は未確認）
- サードパーティへの Agent i の開放は「誰もが作れるエージェント」と言うだけで、API の詳細は未公表
- トレタ（約 2 万店）を子会社化。LINE 経由の予約手数料は 0 円（前回 think で確認済み）
- LINE の国内 MAU は約 9,700 万（要確認）

### メッセージ基盤の API（Web で確認）

- LINE Messaging API: 公式アカウントを友だち追加したユーザーにだけ送れる。任意の LINE ユーザーには送れない
- LINE Login で取れるのは本人プロフィールと「この公式アカウントの友だちか」の判定だけ。友だち一覧は取れない。トークは読めない
- LIFF / LINE ミニアプリ: LINE の中で動く Web アプリ。shareTargetPicker でユーザーが送り先（友だち・グループ）を選び、本人の発言として送れる（LINE 10.3 以降）。エージェントが自律的に送ることはできない
- LINE Bot MCP Server: LINE が実験的に公開（OSS）。中身は公式アカウントからの送信で制約は同じ
- LINE は Siri のメッセージ送信に対応済み。OS のエージェントは LINE で送れるが、第三者アプリは送れない
- Instagram: 個人向け Basic Display API は 2024 年に廃止。Graph API はビジネスアカウント専用。個人のフォロー一覧・DM は第三者が取れない
- Slack・Teams・Discord: bot が DM とチャンネル投稿を送れる。Slack は外部エージェント向けの土台（Agents & AI Apps）を公開
- WhatsApp: Business API で事前同意した相手にテンプレート送信のみ。Meta 管理
- iMessage: 第三者に閉じている
- 端末の電話帳・メール・電話番号は権限を得れば取れる

### 先例（Web・一般知識）

- 日本で LINE に挑んだメッセンジャーはすべて失敗: キャリア 3 社の +メッセージ、Kakao Japan、Viber、Skype
- 日本で LINE の後に伸びた連絡手段は Discord（ゲーム・コミュニティ）と Instagram DM（投稿経由）。どちらも「チャット」でなく別の用途から入った
- 若い層は LINE でなく Instagram を交換する傾向（播口の観察: LINE は親しい人としか交換しない。Instagram も交換しない人はいる）
- PayPay は 2018 年の還元キャンペーンで 1〜2 年で決済習慣を変えた。条件は配布力と目に見える得
- 予定調整 AI の x.ai（Amy）は 2021 年に終了。相手側がシステムに乗っていないと成立しなかった
- 米国の Partiful は集まりの「予定」をリンクで作り、既存メッセンジャーに貼って RSVP・調整を進める形で伸びた。メッセンジャーを置き換えていない
- Airbnb の在庫の 70% 超は Airbnb 限定と推定され、エージェント時代に有利と見る論がある。Booking・Expedia は在庫が非独占で堀が疑問視されている（投資家の意見、事実でなく見方）

- 今日は 2026-09-24。日本で大人数の予約が最も集中するのは 11〜12 月の忘年会。大人数・コース・個室の予約は電話が要る比率が高い（比率は要確認）

## 議論の経過（推論・却下した案）

2026-09-23〜24 の会話で出た推論と、却下した案。

- 播口の出発点: toB は営業を続けないと伸びず急成長しにくい。toC を巻き込み、集客力で toB の契約を取り、toC の増加で収益をスケールさせたい
- AR を「越境客（訪日客・出国する日本人）が店を決める場所」にする筋を採った。国内の日常は Google マップ・食べログで足りるので後
- 越境客はエージェントが最も強い客層なので、エージェント問題は「取った後」でなく同時に来る、と整理した
- 「勝つ」の定義 2 つを比較。1 = 決めるのは AR の評価で画面はエージェントでよい（09-23 方針）/ 2 = 越境客は AR の画面・AR のエージェントで決める。Claude の評価は「2 は画面で勝つ筋が薄い。残るのは食べた後の記録の接点」。播口は 1 を選んだ後、汎用アシスタントを自社でやると決めた
- Claude が出した懸念（出し終えたもの、繰り返さない）: 汎用の勝敗は OS の呼ばれる位置・用事の幅・記憶で決まり、電話の強さは「呼ばれた後の完遂」でしかない / LLM 原価の安さは相手も同じ / 電話の優位は AtoA の進歩で 1 年以内に縮む / 慣性は今の習慣を持つ側（食べログ・LINE・ChatGPT）を守り、Hello は挑む側 / Muse は Instagram・WhatsApp の中に居るので乗り換えを要求しない
- Claude が示した代替（播口は採らず）: 電話完遂と食の記録を Agent i・Muse・ChatGPT に供給する側に立つ（獲得費ゼロ、相手の成長が通話数になる）
- 却下した案 1: アプリ自体にチャットを載せて LINE を直接崩す。Claude の反対理由: 「親しい人以外」の層は Instagram DM が埋めている / 日本で LINE に挑んだ例は全滅 / 予約アプリ内チャットは Airbnb のホスト連絡と同じで用事が終わると止まる / メッセンジャーは別事業で保守費が予約体験と競合する
- 却下した案 2: LINE・Instagram の連絡先を AI で統合した連絡先。Claude の反対理由: 両者とも友だち一覧・DM を第三者に出さない / 「大事なものだけエスカレ」は全会話を読める者（LINE・Meta・OS）しかできない / エージェント同士の会話は相手側にもエージェントが要り、x.ai と同じ壁
- 一方向で成立する形として残したもの: 相手に導入を求めない経路（電話・SMS・メール・リンク）で人に届き、こちら側だけがエージェントを持つ。HelloX の電話が合う
- 播口の再整理: ならばこの汎用エージェントを広めて利用者数を増やせばよい。相手側のエージェント問題は普及で解ける
- Claude の整理: 論点は「利用者を増やす仕組みが製品の中にあるか」。一人で完結する用事は口コミか広告（PayPay 型の費用）。人を誘う用事は送るリンクが招待になり、受け取った側がインストール無しで返事でき、次に幹事になる時に入る（LINE の無料通話と招待、Partiful の RSVP の型）。測るのは招待の K 値と、招待された人が翌月に自分で 1 件作った率
- 最初の用事の候補 3 つ: 会社の飲み会（歓送迎会・忘年会・部署ランチ）/ 友人の集まり / 家族・カップル。Claude の推奨は会社の飲み会。理由は 11 月の忘年会に間に合えば年内に K 値を測れること、大人数・コース・個室で電話が要ること、Slack で bot が居られること、会社払いで単価が高いこと。播口は未決だが「バイラルを作りたい」に同意
- 位置の整理: Hello のアシスタントは「友達との会話の流れの中」には居られない（LINE・OS だけ）。残るのは「決まった後の実行」（電話完結・即時確定・記録）。上流の調整（誰と・いつ・どこ）は LINE と OS に握られる、というのが Claude の見方

## 現在の仮説（播口）

- 汎用パーソナルアシスタントを自社で作る。最初は電話を含む予約体験を完璧にやる
- 連絡先とチャットを、パーソナルアシスタント基盤の新しい体験に置き換える。連絡先は人数を気にしない（LINE・Instagram を交換しない相手も入る）。チャットは基本エージェント同士が行い、本当に大事なものだけ人にエスカレーションされる
- ローンチ後は招待になるリンク（幹事が人を誘う予約）でバイラルに広がる前提
- Muse より先に日本市場を取る。日本は予約が電話に残る比率が高く、Muse・Instinct は米国限定・英語のみ・人の代行つきの段階
- 問いたいこと: この前提で LINE を disrupt できる可能性はあるか。あるなら、何が事実なら採るべきか、どの順で何を作るか。無いなら、同じ資産（電話完遂・200 人の運用・食の記録・Respo の店網）で LINE の外に取れる最大の位置はどこか
