## Claude Code の Slack 接続と定期実行（2026-10-10）

- Slack は 6 ワークスペース（Hello / aisaac / H&G / CodeCast / A2Z / Rise）を自前 MCP（korotovsky/slack-mcp-server、ユーザートークン）で接続。接続名は slack-hello / slack-aisaac / slack-handg / slack-codecast / slack-a2z / slack-rise。H&G 配下（白・H2T2・サンクチュアリ）は slack-handg と同一ワークスペース
- Slack 公式 MCP（mcp.slack.com）と claude.ai 標準コネクタは 1 アカウント 1 ワークスペース固定のため不採用
- トークンは Mac の `~/.config/slack-mcp/<ws>.token`。2026-10-10 時点で codecast / a2z / rise は未配置
- 投稿・リアクションは播口本人名義になる。Claude は投稿前に文面と宛先を会話で確認する
- 定期要約は会社ごとに「知りたいこと」が違うので、会社ごとにジョブを作る。中身は播口が決める。届け先はジョブごとに決める（2026-10-10 変更。当初は全部 Hello の #memo-yuki-hariguchi に集約する方針だったが、チームが読める場所に出す方が価値があるため）
- 投稿は播口のアカウント名義になるので、先頭に「Claude Code が自動生成し播口のアカウントから投稿している」旨の 1 行を固定で付ける
- 仕組みは Mac の `~/.local/bin/slack-digest/`（取得 → Opus で日本語要約 → 投稿）。ジョブは `jobs/<名前>/job.conf`（ワークスペース・対象チャンネルの正規表現・締め・投稿先）と `prompt.md`（要約の観点）の 2 ファイル。launchd ラベルは ai.hariguchi.slack-digest.<名前>
- 集計範囲は「その週の月曜 0:00 〜 日曜 24:00」。投稿は締め時刻（翌週月曜 9:00）以降。1 時間おきと起動時に未投稿の週がないか確認し、Mac が閉じていた週は次に開いたときにさかのぼって投稿する（最大 4 週）。投稿済みの週は `~/.cache/slack-digest/<名前>/posted.json` に記録
- 稼働中のジョブ（いずれも観点を固定せず、全投稿を読んだ上で「グローバルの CEO に伝えるべきこと」を要約側が選ぶ。初回は 2026-10-06 の週）
  - hello-kr: Hello 韓国チーム週次。kr-* チャンネル（アラート・ログ・ニュースフィード系を除く）→ #kr-managers
  - hello-tw: Hello 台湾チーム週次。tw-* チャンネル（同上）→ #tw-managers
