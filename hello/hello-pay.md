# HelloPay

Hello, Inc. の決済代行。法人・体制は hello/base.md。

## 事実（2026-09-25）

- 決済代行（PSP）。PCI DSS あり
- アクワイアラーは今はライフカードのみ（入金は月 2 回）。新しく契約するセゾン等は月 6 回
- カード発行のライセンスは無い

## プロダクト（名称は 2026-09-25 決定）

- HelloPay Payments: オンライン決済（EC・アプリ）
- HelloPay Terminal: 店頭決済（端末レス・決済リンク。RespoPay はこの中）
- HelloPay for Agents: エージェント決済。以下はすべてこの話

# HelloPay for Agents

エージェント（Hello・AutoReserve・外部）がユーザーの代わりに払う仕組み。API は 1 本（「このユーザーが、この店に、この額」）。ユーザー向けの名前は分けず「HelloPay で払う」。発行はライフカードを BIN スポンサーにする（2026-09-25 決定。経緯は decisions.md）。

## 仕組み: 店によって 2 つの道（API の内側で選ぶ）

| | C. HelloPay 加盟店 | A. それ以外の店 |
|---|---|---|
| 払い方 | 保管したユーザーのカードで API で請求 | ライフカードが 1 回だけの番号を出し、エージェントが店の入力欄に打つ |
| 立て替え | なし | あり（保証金プール。月の決済額の 20% 前後。ライフカードはアクワイアラーでもあるので、クレカ請求の入金とプールの相殺を求める。通ればほぼゼロ） |
| ユーザーの明細 | 店の名前。ポイントも付く | 「HELLOPAY」。店名はアプリ内だけ。ポイント対象外や拒否の恐れ |
| 店から見えるもの | 普通のカード決済 | 使い切りの Visa プリペイド。名前欄は本人名か「HELLO MEMBER」（要確認） |

A の流れ: 最初に 1 度だけカード登録（本人認証はここだけ）→ エージェントが払う直前にチャットで OK をもらう → HelloPay が登録カードに請求 → ライフカードが承認額上限の番号を出す → エージェントが打つ。店の本人認証はライフカードが HelloPay の承認記録で通す。買えなければ番号は消え、請求は戻る。

役割: ライフカード＝発行ライセンス・前払式の登録・店への支払い。Hello, Inc.＝商品・カード保管と請求・承認画面・帳簿・損失（不正・誤購入・チャージバック）。

なぜ HelloPay が請求できるか: ユーザーのクレカに載るのは「使い切りプリペイドカードの購入」で、売り手はライフカード（HelloPay が販売と運営）。クレカで Vプリカを買うのと同じ取引。店への支払いはユーザーが自分のプリペイドを使っただけで、HelloPay は送金していない。条件は、アクワイアラーが「プリペイドの販売」の業種で HelloPay を認めること、「金額ぴったり・即時・1 回きり」でも前払式のままと言えること（段階 0 の弁護士確認）。

Stripe の Link も同じ分け方（Link 加盟店は直接、それ以外は使い切りカード）。

## 損益（1 万円あたり。推測。実料率で引き直す）

| | A. クレカ裏付け | B. 銀行口座裏付け | C. 加盟店 |
|---|---|---|---|
| ユーザーから集める手数料 | −200 円 | −30 円 | 0 円 |
| 発行手数料 | −20 円 | −20 円 | 0 円 |
| インターチェンジの分配 | +80 円 | +80 円 | 0 円 |
| 加盟店手数料 − 原価 | 0 円 | 0 円 | +100 円 |
| 不正・誤購入の引当 | −20 円 | −20 円 | 0 円 |
| 合計 | −160 円 | ほぼ 0 円 | +100 円 |

- 黒字は C だけ。入口は A（登録が軽い）。B は後ろ
- 稼ぐ場所: 月額・件数課金 / C の利ざや / 予約デポジットと店側の成果報酬

## 財布はユーザー本人のもの

- カードはユーザー本人の HelloPay アカウントに保存され、どのエージェントからも使える（Link と同じ）。電話番号かメールで 1 回登録。アプリ不要
- 外部は HelloPay の加盟店ではなく、ユーザーの財布を使う許可をもらった代理人。商品を売るのは店で、外部は何も売っていない。外部がユーザーのカードに請求して店に払うと「他人の商品の代金を集めて送金する」ことになり、加盟店規約で禁止、法律上も資金移動業・収納代行になる。外部が自分のサービス料を取るなら、それは通常の加盟店契約で別
- 承認はエージェントのチャット内で取る（Muse・Link と同じ）。ユーザーが HelloPay を見るのは、最初のカード入力欄・明細の「HELLOPAY」・外部の時の通知だけ

## 外部サービス X（例: 旅行の手配エージェント）での流れ

- 初回: X のチャットで「新幹線を取って」→ X が便と金額を出す → ユーザー「お願い」→ 電話番号と SMS のコードを打つ（「X にこの財布を使わせる」許可）。HelloPay アカウントが無い人だけ、続けてカード入力欄が開く（見た目は X。番号は HelloPay に直接届く。規約の同意と本人認証も 1 回）→ X「14,720 円を JR のサイトで払います。よろしいですか」→「はい」→ X「予約できました」＋明細 → スマホに HelloPay の通知（1 タップで止められる）
- 2 回目以降: 「帰りも取って」→ X が金額を出す →「はい」→ 完了。10 秒
- 裏側: X は HelloPay の入力欄を貼るのと、チャットの OK を HelloPay に伝えるだけ。HelloPay がユーザーのカードに請求し、ライフカードが上限つきの使い切り番号を出し、X に渡す。X が店のサイトに打つ。本人認証はライフカードが通す。完了ページを X が HelloPay に返して確定

## 外部への提供の条件

取り分（1 万円あたり）

| | 外部が加盟店以外で払う | 外部が加盟店で払う |
|---|---|---|
| 外部から受ける手数料 | +300 円（3%。上限 3.5%） | 0〜100 円（加盟店に流す動機） |
| Hello, Inc. の原価 | −160 円 | 0 円 |
| 加盟店側の利ざや | 0 円 | +100 円 |
| 残り | +140 円 | +100〜200 円 |

- 社内（Hello・AutoReserve）は原価
- 契約: ユーザー ⇄ HelloPay・ライフカード / 外部 ⇄ HelloPay（代理の規約。誤購入は外部負担、保証金か手数料で相殺）
- 審査: 法人・反社・用途・上限・業種
- 偽の同意への備え: 単回・上限つきの番号、1 件と月の上限、保証金、通知。信用の薄い外部だけ通知側で OK を押させる
- カード番号: 入力欄は HelloPay のもので番号は外部を通らない。使い切り番号は外部に渡して外部が打つ（Stripe と同じ。漏れても 1 件分）。外部の PCI DSS の区分は要確認
- ライフカードの契約に「外販あり」を最初から入れる。UPSIDER の白ラベル提供の前例があるので通る見込み。消費者向け・代理人が使う点で条件は付く

## ロードマップ

- 段階 0（2026-10〜11）: ライフカードと決める。発行 API と速度 / 名前欄 / 本人認証の判定を HelloPay に任せられるか / 損失の分担 / 手数料の分け方 / プールの形（クレカ請求の入金との相殺） / 外販あり。弁護士確認: 即時チャージが前払式のままか、本人確認、代理人の規約。出口は条件書
- 段階 1（2026-12〜2027-02）: 最小構成。社内 100 件で誤請求ゼロ
- 段階 2（2027-03〜05）: テスター公開。電話の先の決済（決済リンク・番号伝達・予約デポジット）。返金・紛争の運用。銀行口座チャージ
- 段階 3（2027 年後半）: Visa / Mastercard のエージェント用トークン。ユーザーの既存カードに Hello 専用の番号を紐づけ、Hello, Inc. はお金の流れに入らない。通すかは発行会社が決めるので、対応した発行会社から順に。使い切りカードは残りの店だけ

Live View 方式（hello/hello.md）は予備。

## 先の話

- 加盟店を増やす: 店が動くのは客の流れが見えた時。差は「払う・予約する」の瞬間にだけ出す（確実に通る・無断キャンセルの保証・返金がチャットで済む）。店選びの順位では優遇しない。失敗した店にだけ通知する。既存の PSP はそのまま受け口を 1 本足させ、Hello 経由が 2〜3 割になった店で乗り換えを取る。この仕組みだけで乗り換えは起きない
- Hello カード（未決）: 自社カードを既定の支払い手段にして、A の −160 円を +100 円前後に反転させる。まず与信なしのデビット・プリペイド型。集客の道具ではない。差は発行会社がトークン対応を出せば消える（12〜18 か月）

## 他社と業界（2026-09-25）

- 収束点: エージェントにカード番号を渡さず、トークンか使い捨ての権限を使い、本人はパスキーかウォレットで承認
- 海外: Visa・Mastercard・Amex がエージェント用トークン。Stripe Link（Muse が採用）・PayPal・Shop Pay は財布側。Stripe の仕組みは日本非対応
- 日本: 本番は Mastercard × 三菱UFJニコス × Evonet の 1 件（2026-05）。Visa の検証に三井住友・ニコス・セゾン。消費者向けに取引ごとの番号を出す事業者は無い。法規制に規定は無い
- 未決着: 誤購入の責任分担 / 本人認証と無人購入の両立
