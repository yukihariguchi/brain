# HelloPay

Hello の決済代行。法人・体制は hello/base.md。ここには HelloPay 固有の立て付けと、Hello（パーソナルアシスタント）のエージェント決済の仕組みを置く。

## 事実（2026-09-25）

- 決済代行（PSP）。カード・Apple Pay・Google Pay・サブスク決済を API で提供。PCI DSS を持つ（審査範囲は要確認）
- アクワイアラーと接続済み。アクワイアラーからの入金は月 6 回（5 日締め）。締めから入金までの日数は要確認
- 発行（イシュイング）のライセンスは持たない

## エージェント決済: ライフカード方式（2026-09-25 決定。決定の経緯は decisions.md）

Hello（パーソナルアシスタント）がユーザーの代わりに店へ払う仕組み。ライフカードを BIN スポンサー（Visa の発行ライセンスを持ち、Hello の商品を載せる発行会社）にして、取引ごとに本人名義の使い切りバーチャル Visa プリペイドを出す。ライフカードは消費者向けの使い切りバーチャル Visa プリペイド（Vプリカ。3D セキュア 2.0 対応、クレカで購入可）を既に運営している。

1 取引の流れ

1. ユーザーは最初に 1 度だけ Hello アプリにクレカを登録する。本人認証（3D セキュア）はこの時だけ
2. エージェントが決済の直前で止まり、チャットで「店・金額」を示して承認を求める
3. ユーザーが承認する
4. HelloPay が登録カードに請求する（2 回目以降は本人認証なしの継続課金の仕組み）
5. ライフカードが、承認額を上限にした本人名義・単回・短期限のバーチャルカードを数秒で発行する
6. エージェントがその番号を店に打つ
7. 店側の 3D セキュアは、発行元のライフカードが Hello の承認記録を根拠に通す。ユーザーは何もしない
8. 完了ページの証拠で確定。買えなければカードは失効し、請求は戻る

役割分担

- ライフカード: 発行ライセンス、前払式支払手段の登録、店側への支払い（Visa 経由）
- Hello（プログラム運営者）: 商品設計、カード保管と請求、承認 UI、帳簿、不正・誤購入・チャージバックの損失
- 店にはユーザーのクレカ番号も Hello 名義も出ない

お金の流れと運転資金

- Hello から出るのは「使い切りカードに入れる金額をライフカードに渡す時」。前払式なので、Hello がライフカードに保証金のプールを置き、発行のたびに引かれる形（A）が有力。ライフカードが立て替えて後で精算する形（B）は要交渉
- A の場合の必要資金は「補充の間隔分の決済額＋ピークの余裕」。5 日ごとの補充なら月の決済額の 20% 前後。返金はプールに戻る
- アクワイアラーからの入金が月 6 回なので、クレカ請求の回収は平均 7〜8 日（締めから入金までを 5 日と仮定）

1 件あたりの損益（1 万円の取引。数字は推測。HelloPay の実料率で引き直す）

| 項目 | 金額 | 前提 |
|---|---|---|
| クレカへの請求コスト | −200 円 | アクワイアラー料率 2.0%。プリペイドチャージは準現金扱いで高くなる可能性（要確認） |
| ライフカードの発行手数料 | −50〜100 円 | 1 枚ごとの固定費（要交渉） |
| インターチェンジの分配 | +80 円 | 店側が払う 1.6% の半分（要交渉） |
| 不正・誤購入の引当 | −20 円 | 0.2% |
| 合計 | −200〜−240 円 | −2.0〜−2.4% |

- 決済単体は赤字。取引量が増えるほど赤字が増えるので、決済で稼ぐ設計にはしない
- 銀行口座チャージ（口座振替・即時振込）に替えると 1 行目が −30 円程度になり、1 件ほぼトントン
- 稼ぐ場所は 3 つ: 月額・件数課金 / HelloPay 加盟店での直接決済（ライフカードを通さず PSP の利ざやが残る）/ 電話予約のデポジットと店側の成果報酬

ロードマップ

- 段階 0（2026-10〜11）: ライフカードと決める 6 つ。取引ごとに出す API の有無 / 発行速度（数秒） / 3D セキュアの判定を Hello の承認記録に委ねられるか / 不正・チャージバック・返金の分担と上限 / 手数料の配分 / プールの形（A か B）と最低残高。並行して弁護士確認: 即時チャージが前払式支払手段のままか、本人確認の要否。出口は条件書
- 段階 1（2026-12〜2027-02）: 最小構成。HelloPay 側はカード保管・請求・返金の帳簿・ライフカード接続・承認画面。エージェント側は番号を打って完了を確認。出口は社内 100 件で誤請求ゼロ
- 段階 2（2027-03〜05）: テスター公開。電話の先の決済（店の決済リンク、電話での番号伝達、予約デポジット）。返金・紛争の運用。銀行口座チャージ
- 段階 3（2027 年後半）: Visa Intelligent Commerce / Mastercard Agent Pay のトークン要求者として入る。対応発行会社のカードは立て替えなしで直接払う。HelloPay 加盟店は API で直接。バーチャルカードは残りの店だけ

Live View 方式（本人のカードをエージェントが打ち、CVV と本人認証を本人が Live View で打つ。hello/hello.md）は、この仕組みが使えない店の予備に降ろす。

## エージェント決済の他社と業界（2026-09-25 時点の事実）

- 業界の収束点: エージェントにカード番号を渡さず、ネットワークトークンか使い捨ての権限を使い、本人はパスキーかウォレット内で承認する
- カード会社系: Visa Intelligent Commerce（エージェント別トークン＋Trusted Agent Protocol）、Mastercard Agent Pay（Agentic Token＋Payment Passkeys。米国全面展開、SG で本番）、Amex ACE（登録エージェントの誤購入を補償）
- 財布系: Stripe Link（使い捨てカード。Meta Muse が採用）、PayPal、Shop Pay、Google Pay（AP2）。Stripe の Shared Payment Token は米・加・欧のみで日本は対象外
- 加盟店側プロトコル: OpenAI ACP・Google UCP・Adyen Agentic。OpenAI のチャット内決済は 2026-03 に終了
- 未決着: エージェントの誤購入の責任分担 / 3D セキュアと無人購入の両立 / 国またぎ
- 日本: 本番は 2026-05-20 の Mastercard × 三菱UFJニコス × Evonet（Agenzo）の 1 件のみ。Visa の APAC 検証に三井住友カード・三菱UFJニコス・クレディセゾンが参加（日本の本番は要確認）。GMO-PG は UCP 対応と Visa ネットワークトークン決済（2026-02）を実装。消費者向けに取引ごとのバーチャルカードを API 発行する事業者は無い。Agent i・楽天 AI は決済直前で止めて本人に押させる。割賦販売法・セキュリティガイドラインにエージェント起点の取引の規定は無い

トークン方式（段階 3）の要点

- ユーザーの既存カードに Hello 専用の別番号を紐づける。Apple Pay の端末専用番号と同じ考え方
- 承認と請求は発行会社が行うので、Visa・Mastercard が対応しても、ユーザーのカードの発行会社が対応していないと使えない
- 店側の決済代行がトークン決済を受けられることが条件。Visa と Mastercard で接続は別
- Hello はお金の流れに入らない。立て替え・チャージバック・前払式の登録が不要
